# Agency → Codex 전환 검토

현재 상태: 2026-10-01 운영 전환 완료. 작업 대기열·서버 함수 9개·예약·Mac 자동 실행을 반영했고 Claude 아침/야간 루틴을 비활성화했다. 사이트에서 입력한 테스트 요청(#723)에 Codex가 같은 방으로 답변(#724)하고 원 요청 완료를 재조회했다. 기존 리서치 #4의 결과 저장도 검증했다.

사이트 입력 → 기존 Supabase에 저장 → 새 작업 대기열 → 이 Mac의 Codex CLI(ChatGPT 로그인) → 연결된 Supabase 플러그인으로 결과 저장 → 사이트 표시.

## 운영에 적용할 변경

- `migration.sql`: 작업 대기열과 연결 상태용 테이블 2개, 요청 감지 트리거, 내부 큐 함수, 토큰 인증 RPC를 추가한다. 테이블에 RLS를 활성화한다. RPC는 작업 가져오기·완료 상태·연결 상태 확인만 제공하며 Agency 콘텐츠를 임의로 읽고 쓰는 기능은 없다. 별도의 긴 비밀 토큰을 검증하고 DB에는 해시만 저장한다.
- `queue-function.ts`: 기존 Agency 서버 함수 9개를 요청 저장용으로 전환한다. Claude/Gemini 모델 호출을 제거한다. 기존 사용자 인증과 내부 예약 인증을 검사한다.
- `cutover.sql`: 기존 예약 작업을 Codex 대기열로 전환한다. 사무실 출퇴근 예약은 유지하고 자동 아침 회의 중지와 야간 off 설정을 존중한다.
- `worker.py`, `install.py`: 이 Mac에 로그인한 사용자 세션에서 요청을 확인하고 Grace 당직·사용자 작업·예약 연구 3개 고정 경로에서 각각 한 작업을 실행한다. 긴 연구가 Grace 채팅을 막지 않는다. 대기 중에는 모델을 호출하지 않는다. 운영 연결을 검증한 뒤 LaunchAgent를 설치한다.
- `agency.html`: 요청을 즉시 완료한 것처럼 표시하지 않고 대기 상태와 Codex 연결 상태를 표시한다.

## 검증과 전환 순서

로컬 테스트 → 명시적 운영 변경 승인 → DB 구조 추가·토큰 연결 → 읽기 전용 Codex 작업 검증 → 서버 함수와 예약 전환 → 사이트 반영 → 실제 요청 결과 재조회 → Claude 루틴 중지.

운영 변경은 사용자의 명시적 승인 후 적용했다. 로컬 테스트 5개·실제 Supabase 조회·사이트 채팅 처리·원 요청 및 결과 재조회·GitHub Pages 배포를 확인했다. 모든 도구/파일 형식/예약 유형의 결과 품질이 검증됐다는 뜻은 아니다.

잠금 화면에서도 컴퓨터가 깨어 있고 로그인 세션이 유지되면 CLI 작업은 실행할 수 있다. 잠자기·종료·로그아웃·네트워크 단절 시 요청은 대기한다. 브라우저 화면 조작이 필요한 일부 작업은 잠금 해제가 필요할 수 있다. ChatGPT 사용 한도와 연결 도구의 권한이 적용된다.

## 가이드 감사와 시니어 기준

10명 모두의 기존 역할·자아·성장 기록을 유지하면서 실행 계약, 특화 전문성, 보는 순서, 판단 도구, 대표 산출물, 함정, 4개 플랫폼 레퍼런스 루틴을 추가했다. `CODEX_OPERATIONS.md`, `SENIOR_STANDARD.md`, `REFERENCE_ROUTINE.md`의 동일 내용을 운영 DB에 저장했고 10/10 구성원과 지침 키를 재조회했다. Mia의 직원 목록 누락도 수정했다. UI의 레벨은 참석 횟수 계산 대신 Iris 평가에 따른 실제 skill.level을 표시한다.

## 복구

기존 서버 함수·DB 함수·운영 지침은 비공개 `backups/`에 보존한다. 전환 문제가 있으면 작업 실행을 중지하고 기존 함수를 복구한 뒤 실행 제공자를 되돌린다. 기존 요청과 결과 데이터는 삭제하지 않는다. 토큰·실행 로그·백업은 Git에서 제외한다.

검증 명령: `python3 -m unittest -v test_worker.py` (이 폴더에서 실행).

## Grace 개인비서 변경

PM 정기 보고를 제외하고 직무 공부는 유지한다. GRACE_PERSONAL.md와 운영 DB의 grace_personal_policy가 편안한 스몰토크·중요한 변화 알림·근거 기반 선호 학습을 규정한다. 선제 대화는 PM 방에서만, 최근 대화/읽음/대기 요청/시간 조건을 확인하며 하루 2회와 6시간 간격은 상한이다. 단순 안부에 전체 조직 감사와 레퍼런스 탐색을 하지 않는다. PM presence는 24시간 idle 당직으로 복구하고 자동 퇴근에서 제외한다. 실제 응답은 이 Mac이 깨어 있고 로그인·네트워크·Codex 사용 한도가 유효할 때 가능하다.
